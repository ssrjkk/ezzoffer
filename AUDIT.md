# Что мешает продукту работать

Проверено по коду и по состоянию рабочей базы (464 вакансии, 1 пользователь, 0 откликов).

## 1. Автоотклик физически не может отправить ни одного отклика

`autoapply.ts:125` отбирает вакансии только с `v.source === "hh"`.
В базе hh = 0 вакансий. Проверено, почему:

- `GET /vacancies` (поиск) без токена → **403 forbidden**. Проверено вживую,
  с разными User-Agent. Поисковый эндпоинт требует токена приложения.
- `GET /vacancy/{id}` (одна вакансия) без токена → **404**, то есть доступен.

Значит требуется раздельное хранение токенов, и сейчас оно нарушено:

| Операция | Какой токен нужен | Откуда берётся сейчас |
|---|---|---|
| Поиск вакансий | токен **приложения** (client_credentials) | `HH_ACCESS_TOKEN`, которого нет |
| Отправка отклика | токен **пользователя** (OAuth) | `users.hh_token` — есть |

`hh.ts:147` требует `HH_ACCESS_TOKEN` для поиска. Это токен нашего приложения
от работодателя, его надо один раз получить по `client_credentials`
(HH_CLIENT_ID + HH_CLIENT_SECRET, которые в проекте уже есть для OAuth) и
кэшировать. У пользователей его нет и быть не может — там пользовательский.

**Фикс:** отдельный `getAppToken()` с кэшем и автообновлением по `expires_in`,
используется только для поиска. Отправка продолжает брать `ctx.accessToken`.
Плюс пагинация: сейчас забирается только первая страница.

## 2. Сопроводительные письма не отправляются вообще

`autoapply.ts:160` передаёт `message: undefined`.
`hh.ts:123` умеет отправлять письмо: `if (ctx.message?.trim()) payload.message = ...`.
Вся инфраструктура писем есть (`cover-letter.ts`, `ai.ts`, UI писем) — она просто
не подключена к автоотклику. Пользователю обещают персонализированные письма
на главной, `/pricing`, `/jobs`. Не отправляется ни одного.

## 3. Подбор вакансий — подстроковый поиск, а не матчинг

`matcher.ts:29`: `keywords.some((k) => haystack.includes(k))`.
Проверено на реальных строках:
- «JavaScript developer» → ложное совпадение `java` (подстрока)
- любая строка с буквой «c» → ложное `c`
- «Менеджер по продажам» → 0 совпадений: в списке только английское `sales`
То есть подбор либо берёт лишнее, либо молчит.

## 4. Скоринг считает мусор

`ai-matching.ts`: 140 навыков через `includes`, веса 60/20/20 заданы константой,
уровень даёт 20 баллов и за совпадение, и за несовпадение (разница 20 против 10),
опыт — `resumeYears >= vacancyYears`. Плюс ошибка: «JavaScript» ≠ «Java».

## 5. Каталог мелкий и медленный (то, что вы отметили)

- 50 вакансий на провайдер, `CATALOG_TTL_MS=21600000` = 6 часов
- `refreshProviders` гоняет всех провайдеров, но результат нигде не измеряется
- нет пагинации: hh отдаёт первые 50 и всё
- нет дедупликации между провайдерами на уровне «одна и та же вакансия у Яндекса и hh»

## 6. `matchesSearch` не умеет «или» и не умеет веса

Все условия — AND. Пользователь хочет «Москва или удалённо» — не может.
Нет понятия «важнее зарплата, чем город».

## Порядок работ

1. hh: публичный поиск без токена + пагинация. **Без этого автоотклик мёртв.**
2. Письма в автоотклике: подключить `personalizeLetter` к отправке.
3. Матчинг: границы слов, русские синонимы, «или», веса.
4. Скоринг: переделать на честный, с объяснением пользователю.
5. Каталог: пагинация, дедуп, частота, метрики.
6. Дальше по воронке: собеседование, отказы, follow-up.
