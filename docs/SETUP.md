# Быстрый старт: от демо к реальной работе

EZOffer работает из коробки с демо-данными. Для реальных откликов на hh.ru и отправки писем нужно заполнить несколько переменных. Здесь — пошаговая инструкция.

---

## 1. Подключение hh.ru (OAuth)

### Что это даёт

Без hh.ru-подключения работают все источники каталога (Работа России, Работа.ру и другие), но **отклики возможны только вручную**: вы видите вакансию → копируете ссылку → откликаетесь на сайте источника.

С hh.ru-подключением:
- Автоотклик по вашим активным поискам (работает в фоне, сам отправляет и пишет в историю)
- Ручной отклик из кабинета одним нажатием
- Синхронизация статусов: HH обновляет «просмотрено / ответили / приглашение» автоматически

### Шаг 1 — создайте приложение на dev.hh.ru

1. Зайдите на <https://dev.hh.ru> → войдите под тем аккаунтом hh.ru, который будет подключён как «системный» (обычно это ваш личный или аккаунт агентства)
2. Перейдите в **«Мои приложения»** → **Создать приложение**
3. Заполните:
   - **Название**: `EZOffer` (любое)
   - **Тип**: `Веб-приложение`
   - **Описание**: `Автоотклики на вакансии hh.ru`
   - **Ссылка на главную страницу**: `https://ваш-домен/` (например `http://localhost:3000` для локальной разработки)
   - **Redirect URI**: `https://ваш-домен/api/hh/callback` — **это важно**, HH шлёт сюда код авторизации

> Если пока нет домена, используйте `http://localhost:3000` для разработки. Потом нужно будет изменить Redirect URI на реальный домен.

4. Нажмите **Создать** — вы попадёте на страницу приложения
5. Скопируйте **Client ID** и **Client Secret** (они видны на странице приложения)

### Шаг 2 — какие права нужны

В карточке приложения на вкладке **Права доступа** (или при первом запросе) подключите:

| Право | Зачем |
|---|---|
| `negotiations` (Отклики) | Создание отклика, чтение статуса |
| `hh_resumes` (Резюме) | Чтение списка резюме, получение hh_id |
| `vacancies` (Вакансии) | Поиск вакансий, чтение деталей |
| `messaging` (Переписка) | Чтение новых сообщений (для статуса «отвечает») |
| `negotiations_history` (История откликов) | Синхронизация статусов |

Без `negotiations` автоотклик работать не будет — это ключевое право.

### Шаг 3 — заполните .env

```env
HH_CLIENT_ID=ваш_client_id_из_карточки_приложения
HH_CLIENT_SECRET=ваш_secret_из_карточки_приложения
HH_REDIRECT_URI=https://ваш-домен/api/hh/callback
```

> **Redirect URI в HH должен совпадать с HH_REDIRECT_URI точно** (включая протокол и завершающий слэш, если есть). Для локальной разработки: `http://localhost:3000/api/hh/callback`.

### Как работает подключение в кабинете

1. Пользователь заходит в **Настройки → Подключение hh.ru**
2. Нажимает **Подключить** → его браузер перенаправляется на `hh.ru/oauth/authorize`
3. Пользователь разрешает доступ → HH редиректит обратно на `/api/hh/callback?code=xxx`
4. Сервер обменивает код на токены, сохраняет в БД (зашифрованно, если `EZOFFER_TOKEN_KEY` настроен)
5. В кабинете появляется статус: «Подключено» с аватаром и именем пользователя

### Если HH отдаёт 403 после подключения

- Проверьте, что приложение на dev.hh.ru — **опубликованное** (в статусе «Доступно»). Новые приложения HH какое-то время работают в тестовом режиме, потом переключаются.
- Для откликов нужен **активный аккаунт на hh.ru** (не пустой новый). Аккаунт без резюме или с заблокированным резюме может получить 403.

## 2. SMTP — отправка писем

Без SMTP работает всё, кроме отправки писем. Восстановление пароля будет молча игнорироваться (письмо не уйдёт, ошибки в логе пользователь не увидит).

### Вариант А — Яндекс.Почта (бесплатно, если есть Яндекс ID)

1. Войдите в Яндекс, перейдите в **Почта** → **Настройки** → **Почтовые программы и IMAP**
2. Включите IMAP и **создайте пароль приложения** (не свой основный пароль!)
   - Пароль даётся для конкретного приложения, его можно отозвать
3. Используйте:
   ```env
   SMTP_HOST=smtp.yandex.ru
   SMTP_PORT=587
   SMTP_USER=ваш@ya.ru
   SMTP_PASSWORD=созданный_пароль_приложения
   SMTP_FROM=ваш@ya.ru
   ```

### Вариант Б — Gmail (с App Password)

1. Google Account → **Security** → **2-Step Verification** — включить (обязательно)
2. **Security** → **App passwords** → создать для «Mail»
3. Используйте:
   ```env
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=ваш@gmail.com
   SMTP_PASSWORD=16-значный_пароль_приложения
   SMTP_FROM=ваш@gmail.com
   ```

### Вариант В — Mailgun (бесплатно 100 писем/месяц)

1. Зарегистрируйтесь на <https://mailgun.com>
2. Добавьте свой домен или используйте sandbox (но sandbox требует авторизованных получателей)
3. В настройках домена → SMTP credentials:
   ```env
   SMTP_HOST=smtp.mailgun.org
   SMTP_PORT=587
   SMTP_USER=postmaster@ваш-домен.mailgun.org
   SMTP_PASSWORD=пароль_из_credentials
   SMTP_FROM=noreply@ваш-домен
   ```

### Вариант Г — свой SMTP-сервер

```env
SMTP_HOST=mail.ваш-сервер.ru
SMTP_PORT=465        # или 587 для STARTTLS
SMTP_USER=username
SMTP_PASSWORD=password
SMTP_FROM=noreply@ваш-домен
```

### Проверка SMTP

После заполнения SMTP_* перезапустите приложение и попробуйте восстановить пароль — письмо должно прийти в течение минуты.

## 3. Домен и TLS

### Зачем домен нужен

- **OAuth hh.ru** требует HTTPS и рабочего Redirect URI. `localhost` работает только для локальной разработки.
- **Telegram-бот** может работать через webhook (нужен HTTPS) или через polling (polling работает и с IP). Для прода бота лучше webhook.
- **Письма** отправляются через SMTP, но SPF/DKIM/DMARC на вашем домене повышают доставляемость.

### Варианты

| Способ | Стоимость | Примечание |
|---|---|---|
| Бесплатный домен (.tk/.ml/.ga) | $0 | Не все подходят для email |
| Cloudflare Registrar | ~$9/год .com | Лучшее соотношение цена/качество |
| Porkbun | ~$8/год | Дёшево, много TLD |
| Ru-center | ~₽700/год .рф/.ru | Для русскоязычного проекта |

### TLS/Caddy (если свой сервер)

Caddy автоматически выдаёт бесплатный сертификат Let's Encrypt:

```env
SITE_URL=https://ваш-домен
SITE_HOST=ваш-домен   # для Caddyfile, должен совпадать с SITE_URL
```

Caddyfile в `deploy/Caddyfile` настроен на автоматический HTTPS.

### Telegram webhook (опционально)

Если домен уже есть и HTTPS настроен, зарегистрируйте webhook:

```bash
curl -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  -d "url=https://ваш-домен/api/telegram/webhook&secret_token=${TELEGRAM_WEBHOOK_SECRET}"
```

Где `TELEGRAM_WEBHOOK_SECRET` — любой случайный токен (он передаётся в заголовке `X-Telegram-Bot-Api-Secret-Token` и защищает от подделки webhook-вызовов).

## 4. Чеклист перед запуском в прод

```env
# Обязательные для работы
SITE_URL=https://ваш-домен          # участвует в OAuth redirect_uri — без HTTPS HH не примет
HH_CLIENT_ID=...                     # без HH не будет реальных откликов
HH_CLIENT_SECRET=...
HH_REDIRECT_URI=https://ваш-домен/api/hh/callback
EZOFFER_TOKEN_KEY=...                # 32+ случайных байт, шифрует токены в БД

# Обязательные для писем (иначе восстановление пароля не работает)
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=user
SMTP_PASSWORD=pass
SMTP_FROM=noreply@ваш-домен

# Для Telegram-бота и админки
TELEGRAM_BOT_TOKEN=...               # от @BotFather
TELEGRAM_WEBHOOK_SECRET=...          # любой случайный токен для защиты webhook
ADMIN_TELEGRAM_CHAT_ID=...           # ваш chat id — сюда приходят уведомления о застоях
OWNER_ID=...                         # тот же chat id для /admin в боте

# Опционально для AI-улучшения резюме
AI_API_KEY=sk-...                    # OpenAI-совместимый ключ; без него работают эвристики
#AI_BASE_URL=https://api.openai.com  # для прокси/совместимых провайдеров
#AI_MODEL=gpt-4o-mini

# Для cron-запусков (если не через встроенный планировщик)
CRON_SECRET=случайный_токен
```

### Сгенерировать EZOFFER_TOKEN_KEY

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Сгенерировать CRON_SECRET

```bash
node -e "console.log(require('crypto').randomBytes(16).toString('hex'))"
```

## 6. Если что-то не работает

### HH OAuth не проходит

1. **Redirect URI mismatch** — проверьте точное совпадение `HH_REDIRECT_URI` в .env и в карточке приложения на dev.hh.ru
2. **Приложение не опубликовано** — до публикации HH может отдавать 403 на авторизацию
3. **Токен не обменивается** — логин/пароль HH мог истечь; в логах сервера будет `401` от api.hh.ru

### Письма не уходят

1. Проверьте лог сервера — там будет ответ SMTP-сервера или ошибка сети
2. Для Gmail/Yandex убедитесь, что используете **пароль приложения**, а не основной пароль
3. Для Яндекса: настройки → **Почтовые программы** → разрешить IMAP

### Бот не отвечает

1. Проверьте `TELEGRAM_BOT_TOKEN` — он должен быть от @BotFather, не от другого бота
2. Для polling: запущен ли `npm run bot:poll` (не упал ли процесс)
3. Для webhook: проверить `curl https://api.telegram.org/botTOKEN/getWebhookInfo`
